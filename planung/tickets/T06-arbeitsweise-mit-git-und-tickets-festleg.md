# T06 · Arbeitsweise mit Git und Tickets festlegen

**Meilenstein:** M0 · Setup und Planung  
**Schicht/Typ:** Setup  
**Schätzung:** 1 h  
**Abhängig von:** T02

## Ziel
Alle arbeiten gleich: ein Branch pro Ticket, Review vor dem Merge.

## Aufgaben
- [ ] In `docs/arbeitsweise.md` festhalten: Branch-Name `T07-rangliste`, Commit-Nachricht mit Ticketnummer (`T07: Tabelle für Rangliste`), Pull Request mit `Closes #<Issue-Nr>`, mindestens ein Review
- [ ] Definition of Done festlegen: Akzeptanzkriterien erfüllt, Tests grün, README aktuell, von jemand anderem gereviewt
- [ ] GitHub Project (Board) mit Spalten Backlog · In Arbeit · Review · Erledigt anlegen und alle Issues hinzufügen

## Akzeptanzkriterien
- [ ] Board existiert und enthält alle Tickets
- [ ] Erster Pull Request nach dieser Arbeitsweise gemerged

## Tests
- [ ] Kein automatischer Test

## Hinweise
Pull Requests helfen auch bei der Verteidigung: Jedes Mitglied hat dadurch Code der anderen gesehen.

## Definition of Done
- [ ] Akzeptanzkriterien erfüllt
- [ ] Tests geschrieben und grün (`pytest`)
- [ ] Von einem anderen Gruppenmitglied gereviewt
- [ ] Quellen in T36 ergänzt (falls etwas Neues verwendet)
